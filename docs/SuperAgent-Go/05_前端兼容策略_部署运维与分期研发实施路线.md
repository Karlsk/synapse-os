# 05. 前端兼容策略、商业私有化交付与分期实施路线图

> 本文档定义 Go 后端与前端的过渡及演进策略（契约兼容 + 静态 UI 快速闭环 -> `synapse-web` 独立演进）、面向企业联网环境的商业私有化单二进制与 Docker 交付规范，以及可直接指导开发落地的 **M0–M5 六阶段研发施工路线图**。

---

## 1. 前端兼容与渐进演进策略

### 1.1 第一阶段：严格兼容 `/api/v1` 契约，内嵌微调版静态 UI 快速闭环

Go 后端在 `internal/web` 完整对齐原版 `/api/v1` 路径、JSON 字段命名（camelCase）、错误码与 SSE 事件帧格式（详见 [../SuperAgent/10_外部API与实时通信协议全量契约.md](../SuperAgent/10_外部API与实时通信协议全量契约.md)），从而在首期即可直接将精简微调后的原版静态 SPA 打包进 `internal/ui`：

- **双模静态资产服务**：
  - **生产模式**：通过 `//go:embed static/*` 将全部静态资产编译进单一 Go 二进制，真正实现单文件交付；
  - **开发模式**：启动传入 `--ui-dir <本地静态目录>` 时直接从磁盘提供静态文件，前端改动刷新浏览器即生效，无需重编 Go 二进制。
- **4 处精准前端微调点（匹配 V1 裁剪边界）**：
  1. **登录页 (`login.html` / `login.js`)**：`GET /api/v1/orgs/registration` 固定返回 `{"open": false}`（后端不暴露 `POST /api/v1/orgs`），界面自动隐藏「注册新组织」入口，保留组织+用户名+密码登录与首次强制改密弹窗。
  2. **Agent 表单 (`agent-form.js`)**：移除 24 种内置性格预设选择器（`GET /api/v1/agents/characters` 返回空数组 `[]` 保持接口兼容，不再强制校验 `character`），表单直接展示自由填写的「角色与指令（`persona`）」文本框，并允许自由选择头像。
  3. **连接器与集成页 (`connectors.js` / `integrations.js`)**：后端 `IntegrationService` 仅返回 `feishu` 与 `dingtalk` 两项企业集成，预置连接器仅播种 `feishu-docs` 与 `dingtalk-tools`，前端自然只呈现飞书/钉钉生态 + 管理员「添加自定义 MCP」入口，无需硬改页面结构。
  4. **供应商目录页 (`models.js`)**：后端 `GET /api/v1/providers/catalog` 在 V1 返回 `claude` 与 `codex`（均带 `maturity: "ga"` 与能力标记），后续 Go 后端每新增注册一个 `AgentRunner` 插件，前端目录自动出现对应卡片。
- **关键契约细节核对（防联调踩坑）**：
  - `POST /api/v1/auth/login` 接收表单字段 `org`、`username`、`password`，成功返回裸 JSON `{userId, username, roles}`（**不包** `ApiResponse` 外壳），失败返 HTTP 401 `{code:"unauthorized", message}`；
  - SSE 帧必须严格按 `event: <type>\ndata: {"type":"...","seq":...,"payload":"..."}\n\n` 输出并在每帧立即 `Flush()`，并显式设置 `X-Accel-Buffering: no` 防止企业 Nginx 反向代理缓冲流式输出；
  - 文本类文件预览（`.md/.txt/.html/.json/.csv`）必须下发 `Content-Type: text/plain; charset=utf-8`、`X-Content-Type-Options: nosniff` 与 `Content-Security-Policy: sandbox; ...`。

### 1.2 第二阶段：向 `synapse-web` 现代前端平滑演进

由于前端与 Go 后端完全通过版本化 REST（`/api/v1`）与 SSE 解耦，后续在 `synapse-web/` 启动 React/Vue + TypeScript 现代控制台时，只需：
1. 开发期配置前端 dev server 将 `/api`、`/mcp`、`/actuator` 代理至 Go 服务 `:18080`；
2. 生产期将 `synapse-web` 构建产物 `dist/` 输出替换进 `internal/ui/static` 嵌入二进制，或由企业网关独立托管静态产物——**Go 后端一行代码无需修改**。

## 2. 商业私有化交付与部署架构

### 2.1 发布产物形态（双形态交付）

1. **独立二进制发行包 (`synapse-os-<version>-linux-<amd64|arm64>.tar.gz`)**：
   ```text
   synapse-os-<version>/
   ├── bin/synapse-server          # 单一静态 Go 二进制（含内嵌前端 + 内嵌 goose SQL 迁移）
   ├── bin/start.sh & stop.sh      # 进程守护、健康探测与 35s 优雅停机脚本
   ├── config/config.yaml          # 核心配置（PG 连接、代理、npm 镜像源、自定义 CA、配额）
   ├── data/                       # 运行期数据卷（secret.key/workspaces/tasks/files/runtime/node...）
   └── logs/                       # 结构化日志输出
   ```
   首次初始化企业租户与首个管理员：
   ```bash
   ./bin/synapse-server migrate --config config/config.yaml
   ./bin/synapse-server bootstrap-org --config config/config.yaml --id acme --name "Acme 科技"
   # 控制台一次性打印 14 位随机管理员密码，首次登录强制修改
   ```

2. **商业私有化 Docker 镜像 + Compose（`synapse-build/`）**：
   - **多阶段构建**：`golang:1.26` 静态编译 `synapse-server` -> 运行镜像基于 `node:24-bookworm-slim`（预装 `ca-certificates curl git ripgrep tini procps`）；
   - **强制非 root 运行**：创建 `uid=10001` 用户 `synapse`（因 Claude Code 禁止在 `root` 下启用免确认权限标志），以 `ENTRYPOINT ["tini", "--", ...]` 回收僵尸子进程；
   - **可写 CLI 全局前缀**：设 `NPM_CONFIG_PREFIX=/opt/cli` 属主为 `synapse:synapse`，镜像预装 `@anthropic-ai/claude-code@latest` 与 `@openai/codex@latest`，同时确保企业管理员在 Web 页面点击「在线升级 CLI」具备写入权限；
   - **企业内网友好挂载**：支持环境变量透传 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` / `NPM_CONFIG_REGISTRY`，支持挂载企业内部根证书文件自动更新系统 CA 与 `NODE_EXTRA_CA_CERTS`；
   - **配套数据库**：Docker Compose 标配 `postgres:17-alpine`（`pg_isready` 健康探针）与持久化卷（`pg-data`、`synapse-data`、`synapse-logs`、`synapse-home`）。
