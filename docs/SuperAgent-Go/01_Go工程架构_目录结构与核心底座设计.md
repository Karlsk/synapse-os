## 2. 基于 `context.Context` 的 Fail-Closed 多租户底座

Go 没有 `ThreadLocal`，而显式传递 `context.Context` 天然比 `ThreadLocal` 更安全、更不容易在 goroutine 间漏传租户上下文：

```go
package tenant

type ctxKey struct{}

const DefaultSentinelID = "superagent" // 仅用于登录前 Logo 与 /mcp 自检，非真实企业

var validCompanyID = regexp.MustCompile(`^[A-Za-z0-9][A-Za-z0-9_.-]{0,127}$`)

// WithCompany 返回绑定了租户 ID 的派生 Context；非法 ID 直接返回错误（调用方必检）。
func WithCompany(ctx context.Context, companyID string) (context.Context, error)

// Require 强取当前租户 ID；缺失即返回 ErrMissingTenantContext（Fail-Closed）。
func Require(ctx context.Context) (string, error)

// Optional 仅用于明确允许无租户的公共端点（如登录前 Logo）。
func Optional(ctx context.Context) (string, bool)

// Path 安全解析 <root>/<companyId>，拒绝 ".." 与非法字符，防止目录穿越。
func Path(ctx context.Context, root string) (string, error)
```

- **跨 goroutine 显式延续**：在开启后台异步回合（如 `ChatService`、`TaskService`、`FileTagger`）时，提供辅助函数 `tenant.Detach(ctx)`——构造剥离 HTTP 请求取消信号（避免 SSE 断连取消后端执行）但**完整保留 `companyID`、`traceID`、`userID`** 的新 `context.Context`。
- **多租户公平轮转器 (`FairRunner`)**：后台定时循环统一调用 `companySvc.ForEachEnabled(ctx, fn)`，内部维护 `atomic.Uint64` 轮转起始租户下标，每家租户在独立 `recover()` 保护内执行，确保单租户异常绝不影响其余租户。
- **商业化租户初始化（替代公网自助注册）**：
  - CLI 子命令：`synapse-server bootstrap-org --id acme --name "Acme Corp" [--admin-user acme]`，校验 slug 规则与 12 个保留字，创建公司、生成 14 位一次性随机密码、创建初始管理员（`must_change_password = true`），并触发 `CompanyStarted`。
  - 平台超管/License 预留接口：通过独立配置 `platform.super-admin-token` 或环境变量控制租户增停与配额调整，不向公网暴露注册路由。

## 3. 认证插件、请求中间件链与会话安全

### 3.1 `Authenticator` 插件接口（一期本地登录，二期零侵入接 OIDC/LDAP）

```go
package spi

type AuthPrincipal struct {
    UserID             string
    CompanyID          string
    Username           string
    DisplayName        string
    Roles              []string
    MustChangePassword bool
}

type Credentials struct {
    Kind     string // "local" | "oidc" | "ldap"
    Org      string
    Username string
    Password string
    Token    string // 供 OIDC/SSO 扩展
}

type Authenticator interface {
    Kind() string
    Authenticate(ctx context.Context, cred Credentials) (*AuthPrincipal, error)
}
```

- **服务端会话存储 (`SessionStore`)**：V1 提供内存（或 PostgreSQL `user_session` 表，推荐落库以支持服务重启不踢人）服务端会话，Cookie 固定 `HttpOnly = true`、`SameSite = Lax`、`Secure` 随 TLS/配置启用；登录态主体标识使用不可变 `UserID`（UUID）。
- **Gin 6 级中间件执行顺序**：
  1. `RecoveryMiddleware`：捕获 panic，记堆栈日志并返回标准 `500 internal_error`；
  2. `TraceIDMiddleware`：校验入站 `X-Request-Id`（`^[A-Za-z0-9._-]{1,64}$`），不合法则生成 32 位 hex，写入 `ctx`、响应头与 `slog`；
  3. `AuthMiddleware`：按路由白名单放行公开端点（登录页、`/api/v1/meta`、`/actuator/health`、`/api/v1/branding/logo`、`/api/v1/auth/login`、`/mcp`、`POST /api/v1/automations/:id/trigger`）；其余端点解析会话 Cookie，未登录时 `/api/*` 返 `401 unauthorized`，页面路径 `302 /login`；
  4. `TenantMiddleware`：从认证主体提取 `CompanyID` 注入 `ctx`；
  5. `PasswordChangeMiddleware`：若主体 `MustChangePassword == true`（且会话未缓存 `password_ok`），拦截除 `/api/v1/auth/*`、`/api/v1/account/password`、`/api/v1/meta`、`/api/v1/branding*` 外的全部 `/api/*` 请求并返回 `403 password_change_required`；
  6. `RBACMiddleware`：管理路由组 `/api/v1/users/*`、`/api/v1/admin/*`、`/api/v1/providers/*` 等校验 `ADMIN` 角色。

## 4. 密码学信封加密与抗 DNS-Rebinding 出口守卫

### 4.1 `SecretCipher`（Go 原生标准库 AES-256-GCM）

- 完全兼容原版密文协议格式，避免任何明文密钥落盘：
  - 主密钥（KEK）：32 字节 Base64，优先读 `SECRET_KEY`，否则读/自动生成 `data/secret.key`（`os.WriteFile(..., 0600)`）。
  - 公司 DEK：首次加解密某租户时在 `sync.Mutex` 保护下生成 32 字节随机数，用主密钥以 AAD = `"company:" + companyID` 加密为 `v1:<base64(nonce12 || ct || tag16)>` 存入 `company.data_key_cipher`，并缓存解码后的 `cipher.AEAD` 于 `sync.Map`。
  - 租户密文：`v2:<companyID>:<base64(nonce12 || ct || tag16)>`，以租户 DEK 加密且 AAD = `companyID`。解密前强校验 `prefixCompanyID == tenant.Require(ctx)`，跨租户立即报错拒止。

### 4.2 `EgressGuard`（修复原版 DNS Rebinding 隐患）

原版仅在发起 HTTP 请求前预查 DNS，存在代理或短 TTL DNS Rebinding 窗口。Go 版可直接利用标准库 `net.Dialer.Control` 在 **TCP `connect()` 系统调用前对最终实际连接的 IP 进行终极拦截**：
1. 请求前校验 scheme（`http`/`https`）、端口白名单（`80`/`443`/`8080`/`8443`）与域名后缀黑名单（`localhost`/`*.local`/`*.internal`，允许管理员配置内网白名单例外）；
2. 自定义 `http.Transport.DialContext`：手动解析全部 IP，逐一校验 `netip.Addr` 为公网地址（封禁 `0.0.0.0/8`、回环、私有网段、CGNAT `100.64.0.0/10`、`169.254.0.0/16`、`198.18.0.0/15`、组播、IPv6 ULA `fc00::/7` 等），并**直接连接校验通过的字面量 IP**（同时保持 TLS `ServerName` 为原 Host），从根源彻底消除 DNS Rebinding！
3. 自定义 `http.Client.CheckRedirect`：限制最多 **6 跳**，每一跳重新执行 URL 规则校验。

## 5. 企业配置、代理/镜像源、错误模型与优雅停机

### 5.1 商业私有化增强配置项

除完整保留原版 `config.yaml` + 环境变量覆盖体系（详见 [../SuperAgent/01_系统架构与多租户安全底座.md](../SuperAgent/01_系统架构与多租户安全底座.md)）外，针对企业联网私有化专门增强：
- `network.http_proxy` / `network.https_proxy` / `network.no_proxy`：统一透传至出站 HTTP 客户端、CLI 子进程、Node.js 下载器与 npm 安装器；
- `network.ca_bundle_file`：支持加载企业内部自签根证书（注入 Go `x509.CertPool` 及 CLI 子进程 `NODE_EXTRA_CA_CERTS`）；
- `runtime.npm_registry`：允许指定企业私有或国内 npm 镜像源（注入 `NPM_CONFIG_REGISTRY`）；
- `runtime.node_dist_mirror`：允许配置 Node.js 下载镜像（默认 `https://nodejs.org/dist`，国内可切镜像源加速）。

### 5.2 统一错误映射、观测性与优雅停机

- **统一错误码**：通过 `errors.As` 将 `apperror` 基类统一映射为原版完全兼容的 JSON 信封 `{"code":"...","message":"...","data":null}`（`invalid_argument` 400、`unauthorized` 401、`password_change_required` 403、`forbidden` 403、`not_found` 404、`method_not_allowed` 405、`conflict` 409、`busy` 409、`too_large` 413、`internal_error` 500）。
- **可观测性补强（修复原版缺失）**：
  - `slog` 统一自动附带 `trace_id`、`company_id`、`user_id`；
  - 在 `internal/core/obs` 正式注册核心业务 Prometheus 指标：`superagent_chat_turns_total`、`superagent_task_runs_total`、`superagent_task_queue_depth`、`superagent_tokens_total`、`superagent_cli_warm_pool_size`、`superagent_im_connected`；
  - 暴露 `/actuator/health`（检测 PG 连接池 ping）、`/actuator/prometheus`。
- **优雅停机编排 (`main.go`)**：监听 `SIGINT`/`SIGTERM`，按严格逆序关闭（总宽限 30 秒）：
  1. 停止接收新 HTTP 请求并排空在途普通请求（SSE 流随根 context 退出）；
  2. 停止所有后台调度循环（`TaskScheduler`、`TaskWatchdog`、`AutomationScheduler`、`SuperAgentLoop`、`MemoryLoop`、`FileTagger`、`ProviderChecker`、`InboxTicker`）；
  3. 优雅关闭飞书/钉钉 WebSocket 长连接与 Claude 热进程池（SIGTERM -> 2s -> SIGKILL）；
  4. 关闭 `pgxpool` 数据库连接池。
