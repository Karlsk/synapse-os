# 08. 知识资产体系：工作文件、项目空间、可复用技能与办公文档阅读

> 本文档定义 SuperAgent 将日常 AI 协作自动沉淀为企业资产的四大核心子系统：工作文件与可插拔多后端存储、项目协作空间、个人/企业两级可复用技能库，以及飞书/钉钉办公文档集成与防 SSRF 通用链接阅读器。全文严格保持技术栈无关。

---

## 1. 工作文件与可插拔多后端存储

### 1.1 文件领域模型与自动资产沉淀

SuperAgent 坚持**“资产留在工作发生的地方”**——用户发给 Agent 的文件/链接、长篇输入，以及 Agent 产出的报告、代码、图片、视频，均统一抽象为单版本 `WorkFile` 记录，自动归档为可检索、可共享的公司资产：

- **5 类文件类型 (`WorkFileKind`，按扩展名自动归类)**：
  - `DOCUMENT`：`md`, `markdown`, `txt`, `pdf`, `doc`, `docx`, `ppt`, `pptx`, `xls`, `xlsx`, `csv`, `json`, `html`, `htm`
  - `IMAGE`：`png`, `jpg`, `jpeg`, `gif`, `webp`, `svg`, `bmp`
  - `VIDEO`：`mp4`, `webm`, `mov`, `m4v`
  - `LINK`：自动捕获的外部 URL 书签（`storage = "link"`, `mimeType = "text/uri-list"`, `size = 0`, `location = <url>`）
  - `OTHER`：其余任意文件
- **4 种来源 (`origin`)**：`chat`（对话中保存或长粘贴）、`task`（任务产出或预读资料）、`delivery`（兼容历史任务交付）、`upload`（用户上传、页内新建或收藏链接）。
- **单版本覆盖与保护规则**：修订产出物时仅在显式指定 `replace_id` 时原地覆盖（要求同 Agent、同 Task 或无 Agent 时的同所有者），且**严格禁止覆盖 `origin = upload` 的用户原始上传文件**（用户上传对 Agent 只读）。
- **标签状态机 (`tagState`)**：单文件最多 **5 个标签**（单标签 ≤20 字、去 `#`、忽略大小写去重）；状态分 `""`（待后台自动打标）、`agent`（Agent 产出时指定）、`auto`（后台 `FileTagger` 补齐）、`user`（人工编辑，**永久锁定，禁止任何自动或 Agent 覆盖**）。
- **5 条自动化采集与入库路径**：
  1. **用户上传与 SHA-256 去重**：单文件上限 **50 MB**，单条消息最多附 **10 个**文件；流式落入租户 `.staging` 暂存目录同步计算 SHA-256，若同范围（同 Agent / 同 Task / 个人空间）已存在同大小同哈希的 `upload` 文件则直接复用已有记录。
  2. **消息投递至工作区**：附在消息中的文件被复制到 `<workspace>/uploads/`（防符号链接攻击与重名自动加 `(2)`），其中 PNG/JPEG/GIF/WebP 同步作为内联视觉输入交给多模态模型，远端 S3 文件先缓存至 `<files>/<company>/.cache/<id>-<updatedAtMs>`。
  3. **Agent 交付物保存**：文本直写（`file_write`）或工作区文件入库（`file_save`，单文件上限可配 `files.max-mb = 200 MB`），自动关联当前消息 ID（渲染内联文件卡）并永久继承所属项目。
  4. **链接自动收藏**：从每条对话/任务输入中按正则提取最多 **10 个** HTTP(S) 链接（单 URL ≤2,000 字），去重记为 `LINK` 记录，**入库时不主动抓取远端内容**。
  5. **长粘贴自动落盘**：任意对话消息正文 `>= 3,000` 字自动存为 `<首行前40字>.md`（`origin = chat`），并在消息流中告知 Agent 该文件 ID，防止开任务时丢失上下文。
  6. **页内在线编创**：支持新建 `.md` 与编辑 `.md`/`.markdown`/`.txt`（正文上限 **200,000 字**）。

### 1.2 个人三层虚拟文件夹 (`FileFolder`)

- **私有视图设计**：文件夹树严格归属每个员工个人（`owner`），最多 **3 层深度**，文件夹名 ≤60 字（禁 `/` 与 `\`，同级不重名）。将共享文件拖入文件夹仅修改该员工自己的放置索引（`file_placement`），**不移动物理存储字节，也不影响其他同事的归档视图**。
- **无损删除提升规则**：删除文件夹 `F` **绝不删除任何文件**；`F` 下的直接子文件夹自动提升挂接到 `F.parentId`（重名自动补 `(2)`），`F` 内的文件放置记录提升至 `F.parentId`（顶层则变为未归档 `""`），`F` 本身标记软删。
- **后台自动归档约束**：`FileTagger` 仅对已创建文件夹的用户，自动归档其**创建于首个文件夹之后**的未归档文件（写入 `placed_by = auto`），永不翻动历史旧文件，也永不覆写 `user` 或 `agent` 摆放结果。

### 1.3 可插拔多后端存储路由 (`FileStorageService`)

| 后端类型 (`type`) | 配置参数与定位属性 (`locates`) | 对象路径与读写特性 |
|---|---|---|
| `internal`（本地磁盘，默认） | 无配置字段 | `<files.dir>/<companyId>/<fileId>/content`；临时文件原子重命名写入；支持本地路径零拷贝直读 |
| `s3`（S3 兼容：AWS S3 / MinIO / R2 / COS） | **定位字段 (`locates=true`)**：`endpoint`、`region*`、`bucket*`、`prefix`<br>**凭证/选项 (`locates=false`)**：`accessKeyId*`、`secretAccessKey*`(密文)、`pathStyle` | 对象键 `<prefix><companyId>/<fileId>`；不支持本地路径，流式打开 |

- **平滑切仓零迁移机制**：
  - **写路由**：所有新文件与覆盖修订统一写入当前活跃渠道（`files.storage.active`）；若覆盖修订的文件原位于旧渠道，新字节写完后自动删除旧渠道字节。
  - **读路由**：每条 `WorkFile` 持久记录其 `storage` 渠道 ID，读取时按历史渠道精确路由（切换后端无需停机迁移存量数据）。
  - **智能渠道 ID 分配**：管理员保存配置时，先执行**真实探活（写入探针对象 -> 逐字节回读核验 -> 删除探针）**；若新配置与已有渠道类型及全部 `locates=true` 字段完全一致，则**原地更新该渠道**实现无感密钥轮换；若桶/前缀/端点变化，则分配新渠道 ID（`<type>-<6位hex>`）保留旧渠道继续服务历史读取。

### 1.4 严格可见性、管理权限与安全内容下发

- **重要规则 — 无全公司公开文件**：文件可见性（`visible`）严格满足三者之一，否则返回 **404**（防探测）：
  1. 文件所有者（`owner`）；
  2. 对 `file.agentId` 具有访问权的用户（Agent 所有者、直接协作者或同项目成员）；
  3. 属于该文件所属项目的成员（`visibleThroughProject`）。
- **管理写权限（重命名、编辑、改标签、删除）**：仅文件 `owner` 或 `file.agentId` 的所有者可执行，否则返 **403**；移动文件夹仅需读可见性。
- **防 XSS 与防嗅探下载/预览策略 (`GET /api/v1/files/{id}/content`)**：
  - 支持 HTTP `Range` 分片拖动（视频播放）；
  - 文本类扩展名（`.md/.txt/.csv/.json/.html/.htm`）在线预览时**强制降级为 `text/plain;charset=UTF-8`**，彻底杜绝 Agent 生成的恶意 HTML 在主站域名下执行脚本；
  - 固定下发安全头：`X-Content-Type-Options: nosniff`、`Cache-Control: no-store`、`Content-Security-Policy: sandbox; default-src 'none'; img-src 'self' data:; media-src 'self'`（仅对 `application/pdf` 省略 CSP `sandbox` 以兼容浏览器内置 PDF 阅读器）；非白名单类型或 `?download=true` 强制 `Content-Disposition: attachment`。

## 2. 协作项目空间 (`Project`)

项目是将**人员、Agent 团队、任务与文件资产**按业务主题聚合的封闭协作单元：

- **成员封闭模型**：项目无 `PRIVATE`/`COMPANY` 公开开关，**严格仅对活跃成员可见**（非成员一律返回 `404`）。
- **两种角色与两种可逆状态**：
  - 角色：`owner`（创建者自动为所有者且不可被移出，独享编辑、归档/重开、增删成员权）与活跃 `member`（成员移除置 `active = false` 保留审计行）。
  - 状态：`ACTIVE` <-> `ARCHIVED`（可逆归档，**无硬删除接口**）。
- **资源归属与归档语义**：
  - **Agent**：每个标准 Agent 至多归属 **1 个**项目（`SUPER` 禁止入项目；已归档项目禁止加新 Agent）；Agent 所有者可自由迁入/迁出自己拥有的 Agent，迁出不影响已产生的历史任务/文件归属。
  - **Task 与 File**：创建瞬间通过跨模块 SPI（`ProjectAccess.recordTask` / `recordFile`）永久固化为所属任务/Agent 当时的项目归属。
  - **归档只读保障**：项目一旦 `ARCHIVED`，成员仍可查阅全部历史对话、任务与文件，但项目内所有 Agent 立即变为**只读**，拦截新消息发送；调用 `reopen` 即可恢复协作。

## 3. 可复用技能体系 (`Skill`)

技能是将个人摸索出的优秀工作规范沉淀为组织级标准（Markdown + 示例配图）的核心载体。

### 3.1 两层空间、升降级与 3 个预置种子技能

- **空间与权限 (`space`)**：
  - **个人空间 (`personal:<userId>`)**：仅创建者读写（他人访问返回 `404`）。
  - **企业空间 (`company`)**：全公司员工可读与绑定，**仅公司管理员可创建、编辑、删除及在个人/企业间升级或降级**（普通用户越权返 `403`）。*(注：数据列预留 `team:<path>` 前缀，当前版本仅开放 `personal` 与 `company`。)*
- **3 个企业预置种子技能 (`SkillSeeds`)**：公司首次初始化且零技能时幂等写入 `company` 空间（由 `skill.seeded` 保护，人工删除后永不复种）：
  1. **`写作规范`**（分类 `写作`）：结论先行、单段 ≤4 行、短句 ≤40 字、禁用“赋能/抓手/闭环/颗粒度/底层逻辑”等空洞黑话、中英文空格规范与自查清单；
  2. **`画图规范（设计师）`**（分类 `设计`）：单图单结论、单向流、至多 3 色、字体/字号/间距规范、PNG `@2x` + 可编辑 SVG/Mermaid 交付；
  3. **`运营文案`**（分类 `运营`）：`钩子 -> 利益点 -> 行动` 结构、各渠道字数红线（App Push / 短信 / 社群 / 海报）、禁用绝对极限词、一次给 3 版并明确推荐 1 版。

### 3.2 图片附件、删除确认卡片与渐进披露注入

- **技能配图**：存储在 `<skill.dir>/<companyId>/<skillId>/images/<name>`，沿用 5 MiB 魔数嗅探（仅 PNG/JPEG/GIF/WebP，扩展名强制由魔数决定），Markdown 中以 `![说明](images/<name>)` 引用。
- **人机确认删除工作流 (`SkillDeletion`)**：当 Agent 在对话中调用 `skill_delete` 时（任务中直接禁止），并不立即删技能，而是创建 `PENDING` 状态的确认卡片锚定到当前 `messageId`；**仅发起该轮对话的请求者本人**点击确认卡片后，服务端复核权限并执行软删除（`deleted = true`）。
- **绑定快照与防膨胀渐进披露**：
  - Agent 绑定有序技能列表（`SUPER` 禁绑）；创建任务时将该 Agent 当前技能列表**快照冻结**到任务上（无 Agent 的直接任务默认装配所有者全部可用启用技能）。
  - **运行期安全物化**：回合启动前，先校验 `<workspace>/.superagent` 与 `.superagent/skills` **非符号链接**，清空并写入每个技能的 `SKILL.md` 与 `images/*`；在系统提示词中**仅注入一行一条的轻量 `# Skills` 索引**（`- <名称> — <触发说明> (<SKILL.md 绝对路径>)`），引导模型仅在适用时按需读全文，极大节省上下文 Token。

## 4. 企业办公文档集成与防 SSRF 通用链接阅读器

### 4.1 飞书 / Lark 文档与钉钉知识库双平台集成

两套办公文档工具统一受 `McpGrants.requireDocAccess` 约束（**SuperAgent 后台轮次全面禁用；SuperAgent 实时对话仅限只读；普通对话与任务开放读写**），单次读取均截断 **30,000 字**并加注防提示词注入声明，但员工身份鉴权机制各异：

| 平台 | 启用条件 | 员工身份模拟机制 | 写入机制 |
|---|---|---|---|
| **飞书 / Lark 文档** (`FeishuDocTools` — 6 工具) | `feishu` 集成就绪 | 使用员工个人 `feishu-docs` **OAuth Bearer 令牌**直调开放 API（随集成配置自动切 `open.feishu.cn` / `open.larksuite.com`）；支持 `/docx/` 与 `/wiki/` 节点解析 | 调 `/docx/v1/documents/blocks/convert` 将 Markdown 转为块结构，剥离只读 `table.merge_info` 后写入（替换先批量删根子节点再写） |
| **钉钉知识库** (`DingTalkDocTools` — 5 工具) | `dingtalk` 集成就绪 | 使用**企业应用 Token**（缓存并提前 300s 刷新）+ 将员工绑定 `userid` 换取缓存的 `unionid`，每个请求传入 **`operatorId=<unionId>`** 由钉钉服务端按该员工真实权限鉴权 | 调 `/v1.0/doc/suites/documents/{key}/overwriteContent` 直接以 `contentType = "markdown"` 写入 |

### 4.2 防 SSRF 通用链接阅读器 (`LinkReaderService`)

1. **安全抓取与缓存**：
   - 强制 `EgressGuard.PUBLIC_ONLY`（公网 IP + 端口白名单），关闭自动重定向，人工逐跳跟随最多 **`6` 跳**并**每跳重检 SSRF**；
   - 连接超时 10s / 读取超时 30s / 响应体硬上限 **`20 MB`**；
   - 按 `(companyId, userId, normalizedUri)` 维护 **200 条、10 分钟 TTL 的内存 LRU 缓存**（使任务创建期预读成功的链接在执行期秒级命中）。
2. **5 级数据源路由优先级**：

| 顺位 | 数据源 | 匹配规则与解析特性 |
|:---:|---|---|
| 1 | **飞书文档（授权优先 + 公开兜底）** | 匹配 `feishu.cn` / `larksuite.com` / `larkoffice.com` / `feishu.net` 的 `/docx/`、`/wiki/`（拒绝表格/多维表并给导出建议）。若当前用户已授权 `feishu-docs` OAuth，**优先走官方 API 读私密文档**；失败（如外部公司公开文档）则自动降级走匿名网页 API，BFS 翻页拉取 `client_vars`（最多 **80 页**），通过 `FeishuBlocks` 将标题/列表/待办/代码块/引用/表格渲染为标准 Markdown，缺失子块或超页标记 `complete = false` |
| 2 | **Google Docs / Sheets / Slides** | 匹配 `docs.google.com/(document\|spreadsheets\|presentation)/d/<id>`，直接导出 `/export?format=txt` 或 `csv`；拦截登录页跳转 |
| 3 | **GitHub** | 支持 `raw.githubusercontent.com`、`gist.github.com`、仓库根路径（读 README）、`/blob/` 转 raw、`/issues/` & `/pull/`（API 正文 + 最多 **5 页 × 100 条**评论）；清晰区分 404 私有库与 403/429 匿名限流 |
| 4 | **微信公众号文章** | 匹配 `mp.weixin.qq.com/s*`，带 Referer 提取 `#activity-name` 与 `#js_content` 转 Markdown；识别验证码拦截给出下载建议 |
| 5 | **通用兜底 (`GenericSource`)** | 拦截 401/403/登录页；按类型分流：（a）**PDF**（含 `%PDF` 魔数）提取纯文本并拒空扫描件；（b）**HTML** 剥离导航/脚本/页脚/表单等噪声标签，择优定位 `<article>/<main>/#content/.markdown-body` 主容器转 Markdown，正文 `< 80` 字判为纯前端 SPA 拒绝；（c）纯文本/JSON/XML/CSV 原样返回；（d）二进制给出下载上传建议 |

3. **分页阅读与任务前置校验**：`read_link` MCP 工具支持 `start` 偏移按 **20,000 字/片** 分页阅读（附认证来源标注、完整性告警与防注入声明）；任务创建时并行预检最多 **8 个**链接（90 秒总限时），任意不可读直接报 HTTP `409` 中止创建。
